## 1. WHAT IS DAYTONE?
DayTone is a Flask-based web application that serves as an intelligent mental wellness 
tracker. Instead of just letting users record their moods, DayTone uses:
- Natural Language Processing (NLP) to read the user's journal notes and calculate sentiment.
- Machine Learning (ML) to analyze sleep patterns, stress levels, social interactions, and mood history to predict the user's risk of "burnout" (Low, Medium, High).
- Rule-based logic to generate daily tailored suggestions (activities to complete or habits to avoid).
- Premium User Interface (UI) components, including a D3.js heatmap showing mood patterns over a year, and a Three.js WebGL canvas displaying a glowing, morphing "Mood Orb" representing their current state.

## 3. CORE TECHNOLOGIES & STACK
To understand the code, you should understand the primary technologies being used:

- **Flask**: A lightweight, flexible Python web framework. It handles incoming requests, directs them to the correct code (routing), and returns HTML templates.
- **SQLAlchemy (Flask-SQLAlchemy)**: An Object-Relational Mapper (ORM). It allows us to write database queries using Python code instead of raw SQL statements.
- **SQLite**: A lightweight SQL database file located in the `instance/` folder. It is excellent for local development. In production, DayTone is configured to refuse SQLite and require a production-grade database like PostgreSQL.
- **NLTK (VADER)**: The Natural Language Toolkit. It contains a rule-based sentiment analyser called VADER that takes a string of text (e.g. journal notes) and returns a sentiment score between -1.0 (very negative) and +1.0 (very positive).
- **Scikit-Learn**: A machine learning library. We use it to train classification models (Random Forest, Decision Tree, Logistic Regression) to detect burnout risk.
- **Chart.js**: A front-end Javascript library used to draw beautiful graphs (line charts, bar charts, scatter plots, and donut charts) on the dashboard.
- **D3.js**: A powerful Javascript library for manipulating data-driven documents. We use it to draw the dynamic SVG grid for the GitHub-style wellness heatmap.
- **Three.js**: A WebGL library that makes it easy to run 3D graphics in the browser. We use it to render a premium glowing "Mood Orb" with custom mathematical shaders.
- **Flask-Talisman**: A security extension that sets HTTP response headers (like Content Security Policy, XSS protection, and frame options) to defend the site from hackers.
- **Flask-Limiter**: Restricts how many times an IP or user can hit an API endpoint in a given period to prevent brute-force attacks on forms.

## 4. DATABASE DESIGN (MODELS & SCHEMAS)
DayTone's database is structured in `app/models.py`. It has 5 main tables (classes):

### A. User
Represents a registered user of the system.
- `id` (Integer, Primary Key): Unique identifier.
- `name` (String): Display name of the user.
- `email` (String, Unique, Indexed): User's sign-in email address.
- `password_hash` (String): Secure password hash generated using `scrypt` hashing. Raw passwords are never stored.
- `role` (String, default "user"): Can be "user" or "admin".
- `created_at` (DateTime): When the user registered.
- Relationships: Has a 1-to-1 relationship with `UserProfile` and a 1-to-many relationship with `MoodLog`.

### B. UserProfile
Contains optional profile data and habits.
- `id` (Integer, Primary Key).
- `user_id` (Integer, Foreign Key): Links to `User.id` with a cascading delete (if user is deleted, delete profile too).
- `age` (Integer): User's age.
- `gender` (String): Female, Male, Other, or null.
- `occupation` (String): Profession.
- `preferred_activity` (Enum): Walk, Yoga, Music, or Reading. Used to customise suggestions.
- `daily_reminder` (Boolean): If true, user wants daily reminder emails if they haven't logged today.

### C. MoodLog
Represents a daily self-reflection entry made by a user.
- `id` (Integer, Primary Key).
- `user_id` (Integer, Foreign Key): Links to `User.id`.
- `log_date` (Date, Indexed): The date this log belongs to. Users can only have one log per date (`uq_user_log_date` unique constraint).
- `mood_score` (Integer, 1 to 5): 1=Sick, 2=Sad, 3=Anxious, 4=Calm, 5=Happy.
- `sleep_hours` (Float): Amount of sleep obtained.
- `stress_level` (Integer, 1 to 5): Level of stress experienced.
- `activity_done` (Boolean): Whether they did a wellness activity.
- `social_interaction` (Integer, 1 to 3): 1=Alone, 2=Group, 3=Social.
- `notes` (Text): Optional daily journal text.
- `sentiment_score` (Float, -1.0 to 1.0): Computed using NLP VADER on notes.
- `burnout_risk` (Enum): Low, Medium, or High. Predicted by ML or rules.
- `created_at` / `updated_at` (DateTime): Timestamps for auditing.
- Relationships: Links to `User`, has a 1-to-many link with `Suggestion` and `BurnoutHistory`.

### D. BurnoutHistory
Stores historical machine learning execution logs.
- `id` (Integer, Primary Key).
- `user_id` (Integer, Foreign Key): Links to `User.id`.
- `log_id` (Integer, Foreign Key): Links to `MoodLog.id`.
- `prediction` (String): High, Medium, or Low.
- `confidence` (Float): The probability score (from 0.0 to 1.0) of the model prediction.
- `algorithm_used` (String): Which algorithm made this prediction (e.g. "RandomForest", "Rules").

### E. Suggestion
Actionable suggestions linked to a specific daily log.
- `id` (Integer, Primary Key).
- `user_id` (Integer, Foreign Key): Links to `User.id`.
- `log_id` (Integer, Foreign Key): Links to `MoodLog.id`.
- `suggestion_text` (Text): The custom wellness tip.

## 5. HOW DAYTONE WORKS: STEP-BY-STEP DATA FLOWS
Let's look at how data moves through the application during normal actions.

### Flow 1: User Sign-Up & Sign-In
1. **Registration**: The user fills out `app/auth/forms.py` (RegistrationForm). 
   - Route `auth.register` checks if the email is already taken.
   - If the user fills out the secret admin registration code (stored in `.env`), their role is saved as "admin".
   - Passwords are encrypted using Werkzeug's `generate_password_hash` with `scrypt` encryption and saved.
2. **Login**: The user enters their email and password in the LoginForm.
   - Endpoint `auth.login` checks credentials using `check_password_hash`.
   - The user session is initiated using Flask-Login's `login_user()`.
   - To defend against brute force, this endpoint has a rate limit of 5 requests per minute.
   - To prevent hackers from guessing which emails are registered, the app logs a secure SHA-256 hash of the email rather than the raw text in its warning logs if authentication fails.

### Flow 2: Creating a Mood Log
When a user submits a new log via `mood.log_mood` route:
1. **Form Validation**: The app verifies the form data (mood, sleep, stress, social, activity, notes).
2. **Duplication check**: It checks if a log already exists for this date. If yes, it redirects them to history.
3. **Sentiment Analysis**: It takes the text notes and sends them to `app/nlp/sentiment.py`. 
   - `get_sentiment_score()` runs VADER's `polarity_scores()`. It parses the notes and outputs a compound score from -1.0 to 1.0.
4. **Feature Compilation**: The app calls `build_features()` in `predictor.py`.
   - It fetches the last 7 days of logs for the user to compute rolling aggregates: `avg_mood_7d`, `avg_stress_7d`, `avg_sleep_7d`, `consecutive_bad_days` (moods <= 2), and `mood_variability` (standard deviation of mood scores).
   - It sets `is_weekend` (1 if log_date is a Saturday or Sunday, else 0).
5. **Burnout Risk Prediction**:
   - The compiled 12 features are sent to `predict_burnout()`.
   - The function attempts to load the serialized machine learning model `model.pkl`.
   - If loaded, the model evaluates the features and returns a classification: Low, Medium, or High, along with a confidence probability.
   - If the model pickle file is missing or corrupted, the system falls back to a deterministic rule-based scoring algorithm.
6. **Persistence**:
   - The `MoodLog` is saved in the database.
   - A `BurnoutHistory` record is written, capturing the confidence score and the algorithm name.
7. **Cache Invalidation**: The dashboard caching database query is invalidated for this user so that their graphs update immediately.
8. **High-Risk Alerts**: If the predicted burnout risk is High, the system triggers `send_high_risk_alert()` inside `app/utils/mailer.py` to notify the system administrator immediately via email.

### Flow 3: Dynamic Suggestions
Every time a log is created or updated, suggestions are updated via `_replace_suggestions()` in `app/mood/routes.py`:
1. It deletes any old suggestions linked to the log.
2. It calls `get_suggestions()` in `app/utils/suggestions.py` with parameters: burnout risk, sleep, stress, social interaction, physical activity done, and their preferred activity (from user profile).
3. Suggestions evaluates a list of conditional rules (using python lambda functions). Examples:
   - Sleep < 5 hours -> Add "DO: Drink water or chamomile tea tonight." and "DON'T: Consume caffeine after 2:00 PM."
   - Stress >= 4 -> Add "DO: Practice a 5-minute guided box breathing session." and "DON'T: Accept new responsibilities today."
   - No activity -> Add "DO: Engage in a light 10-minute [Preferred Activity] to boost your endorphins."
4. These are saved to the `Suggestion` table and displayed on the user's dashboard.

### Flow 4: The Interactive Dashboard & 3D Mood Orb
When the user visits `/dashboard`:
1. **Aggregate metrics**: `dashboard_data` calculates average sleep, average stress, average mood, and current logging streak.
2. **Chart data mapping**: Raw historical log parameters are passed to `charts.js` using a window global variable `window.DAYTONE_CHARTS`.
3. **Chart Rendering**: Chart.js generates:
   - Line chart showing mood scores over time.
   - Bar chart showing sleep hours.
   - Line chart showing stress levels.
   - Scatter plot displaying correlation between sleep hours and mood scores.
   - Doughnut chart showcasing the user's overall burnout risk distribution.
4. **3D Mood Orb**:
   - If a log exists for the current day, its parameters are sent to `mood-orb.js` (ambient.js/mood-orb-three-shader.js).
   - A WebGL canvas initialized by Three.js displays a floating 3D sphere.
   - The color of the sphere changes according to the user's mood score: Red (Sick), Orange (Sad), Yellow (Anxious), Emerald Green (Calm), and Green (Happy).
   - In `ambient.js`, a 3D Simplex Noise shader program recalculates the coordinates of the sphere's surface vertices in real-time, causing it to wave and warp organically.
   - It listens to mouse movements. Sudden cursor drags cause the orb to deform faster and spin, returning to a calm state slowly.

### Flow 5: D3.js GitHub-Style Mood Heatmap
When the user clicks the "Heatmap" page:
1. The page renders the container `div id="heatmap"`.
2. `heatmap.js` calls `/api/heatmap?year=2026` to fetch logs.
3. D3.js creates an SVG container containing 53 columns representing weeks, with 7 rows representing days of the week.
4. Each day is represented as a square cell (`<rect>`). The cell's fill color is mapped to their daily mood score (grey for no logs, red to green for scores 1-5).
5. Hovering over a cell triggers a tooltip showing the date, mood name, and burnout risk classification.
6. Hovering over the mood legend items (e.g. Happy) dims all cells in the heatmap except for the ones matching that specific score.
7. Clicking a cell updates a detail card. If a log exists, it shows user details and an "Edit check-in" button. If empty, it shows a "Log this day" button pointing to a retrospective logging URL.

### Flow 6: Generating PDF Reports & Exporting CSV Data
- **PDF Report**: The route `/report/pdf` calls `build_pdf_report()` in `pdf_report.py`. It uses ReportLab to create an in-memory `BytesIO` buffer. The code writes a styled header, a summary table, a burnout risk breakdown, a table displaying the 10 most recent logs, and their top action recommendations. It serves the PDF with security headers.
- **CSV Export**: The route `/export/csv` fetches all user logs. To prevent memory bottlenecks if a user has thousands of logs, it uses a generator function and Flask's `stream_with_context` to stream rows of CSV text to the browser chunk-by-chunk. It strips notes from the export unless the parameter `?include_notes=1` is provided.

### Flow 7: Admin Panel Management
If the user's role is "admin":
1. They can access `/admin/dashboard` which queries `platform_stats()` in `analytics.py`. It displays: total users, active users logging in the last 7 days, platform-wide average mood and sleep, and total high-risk users.
2. Under `/admin/users`, they can view all users, search by name/email, or filter by role.
3. They can drill down into a specific user (`/admin/user/<id>`), which displays that user's personal dashboard and complete logging history.
4. From the detail page, admins can demote/promote roles, delete user profiles, edit a user's incorrect log parameters (recalculating sentiment/ML predictions on submit), or delete a user's logs.
5. If an admin demotes or deletes their own account, the system automatically signs them out and redirects them to the guest register/login screens.

## 6. THE MACHINE LEARNING PIPELINE
DayTone contains a complete Python machine learning training script in `app/ml/train.py`.

### Step 1: Generating Synthetic Data (`generate_data.py`)
To run a machine learning demo without violating privacy, we generate synthetic data:
- `generate(rows=5000)` creates a Pandas DataFrame containing 5,000 logs.
- It randomizes parameters (mood, sleep, stress, activity, social, sentiment) using Gaussian (normal) distribution models to simulate realistic human patterns (e.g., lower sleep is correlated with lower mood and higher stress).
- It labels each row using the rule-based rubric (`label_row()`) to ensure consistent training.
- The output is saved to `training_data.csv`.

### Step 2: Model Training & Evaluation (`train.py`)
When you run `python -m app.ml.train`:
1. It loads `training_data.csv`.
2. It splits the dataset into features (12 input columns) and targets (`burnout_risk`).
3. It does an 80/20 train/test split, stratifying by risk to ensure equal distribution in both sets.
4. It initializes three models:
   - **Decision Tree Classifier**
   - **Logistic Regression** (max_iter=800)
   - **Random Forest Classifier** (n_estimators=150)
5. It evaluates each model using **Stratified 5-Fold Cross-Validation** (splitting the training data 5 times to check stability).
6. It fits each model on the test data and compares their holdout accuracies.
7. It selects the model with the highest holdout accuracy (historically **Random Forest**, yielding ~99% accuracy due to the clean logical structures of the synthetic dataset).
8. It serializes the winning model payload (model, name, feature list) using pickle and writes it to `model.pkl` in the ml folder, along with a timestamped backup file.
9. It writes metrics to `model_metrics.json` and meta statistics to `model_meta.json`.

## 7. SECURITY & PRODUCTION CHECKLIST
DayTone implements strict production-grade security patterns. During application startup, `validate_runtime_config()` checks the environment and crashes (raises `RuntimeError`) if the following safety practices are violated in a production setting:

- **Secret Key**: Must be set to a secure, private value in production. Dev defaults like "dev-only-insecure-key" or "change-me" are blocked.
- **CSRF Protection**: Form inputs use Flask-WTF which validates unique tokens per request, preventing Cross-Site Request Forgery.
- **Content Security Policy (CSP)**: Managed by Talisman. Restricts assets (CSS, Javascript, Images) to local files and explicitly trusted CDNs (like Google Fonts, Chart.js, Three.js, Lucide). It blocks raw inline scripts (`'unsafe-inline'` is restricted only to trusted bootstrap classes) and unauthorized script injectors.
- **Session Security**: Session cookies are configured with `HttpOnly` (blocks Javascript read access) and `SameSite='Lax'` (defends against cross-site request leakage). The cookie lifetime is restricted to 8 hours.
- **Redirect Validation**: Safe URL checking (`safe_next_url`) blocks open-redirection attacks on the login page by rejecting protocol-relative redirect URLs (like `//evil-website.com`).
- **Database Restriction**: Production environments reject SQLite files and require a robust client-server database (e.g. PostgreSQL) via `DATABASE_URL`.
- **Limiting Request Payloads**: Max upload content length is capped to 2MB (`MAX_CONTENT_LENGTH`) to avoid DDoS upload attacks.
- **Admin registration checks**: `ADMIN_REGISTRATION_CODE` must be set, must be at least 16 characters in length, and memory-backed rate limits are disabled in favor of a shared Redis cache storage (`RATELIMIT_STORAGE_URI`).

## 8. SUMMARY OF RECENT IMPROVEMENTS
The current codebase incorporates several vital enhancements over previous versions:
- **Security & Data Privacy**: Implemented AES-256 Fernet symmetric encryption at rest for sensitive daily journal entries (`notes` column) with a graceful plain-text fallback. Formulated a secure GDPR erasure workflow (cascading user accounts deletion) and a data portability system (streaming full user database details as structured JSON).
- **Machine Learning & NLP Pipelines**: Built a 100-sample semi-real pilot validation dataset incorporating physiologically plausible wellness correlations (e.g. sleep/stress inverse correlation) to act as an independent holdout set. Models now compute full test-set accuracy, Stratified 5-Fold cross-validation, and a 3x3 validation confusion matrix with precision, recall, and F1-scores. Added explainability logic parsing risk drivers (like sleep dropping below 7-day average) and integrated an optional distilled BERT sentiment analysis wrapper (with VADER fallback).
- **Proactive Insights & Analytics**: Added Pearson correlation coefficient analytics on recent user logs to display sleep vs. mood and stress vs. mood trend correlations on the dashboard. Embedded a feedback loop allowing users to rate whether the burnout prediction matches their actual state, which aggregates into cohort accuracy statistics on the admin panel.
- **Accessibility & User Customization**: Designed a "Calm / Reduced-Motion" mode setting that disables Three.js 3D orb Simplex noise warping and Chart.js transition animations for users with motion sensitivity. Integrated Web Speech API speech-to-text voice journaling on the check-in screen.
- **Engagement & Interventions**: Added a user onboarding flow for first-time visitors with zero logs. Built a High-Risk compassionate intervention card featuring crisis support helpline resources and a 60-second guided box breathing utility. Implemented personal goal setting and tracking (targets for sleep, mood, active days, etc.) with animated progress bars.
