           DAYTONE MOOD ANALYSER - COMPREHENSIVE PROJECT EXPLANATION

This document provides a comprehensive technical overview, architectural blueprint,
feature implementation breakdown, and operational guide for DayTone.

--------------------------------------------------------------------------------
1. EXECUTIVE SUMMARY & OBJECTIVE
--------------------------------------------------------------------------------
DayTone is a self-hosted, production-ready, and GDPR-compliant Flask web
application designed for personal mental wellness tracking and burnout prediction.
It acts as a private, secure journal and analytics engine that allows users to
log daily metrics (mood, sleep, stress, activity, and social interaction) along
with personal journal reflections. 

Unlike typical mental health applications that process sensitive data in external
proprietary clouds, DayTone uses local natural language processing (NLP) and
on-device Machine Learning (ML) to analyze burnout risk, compute sentiment,
and generate wellness tips. It is built to run on $0 student-friendly free-tier
hosting (Docker, PostgreSQL, and Redis) while implementing enterprise-grade
security, accessibility, and performance optimizations.

3. CORE FEATURES & IMPLEMENTATION DETAILS
--------------------------------------------------------------------------------

A. DAILY LOGGING ENGINE & LOCAL NLP
- Daily Check-ins: Users log their mood (1-10 scale), sleep duration (hours),
  stress levels (1-10 scale), physical activity (yes/no), social interaction
  (yes/no), and reflection journal notes.
- Sentiment Analysis: Journal notes are processed locally using the NLTK VADER 
  lexicon. VADER computes positive, negative, neutral, and compound scores, 
  which are used to determine user sentiment without transmitting text to 
  external APIs.

B. 3D WEBGL SHADER ORB
- Dynamic Visual Feedback: The dashboard renders an interactive 3D orb using 
  THREE.js.
- Simplex Noise Deformation: A custom WebGL shader deforms the orb's vertices
  and changes its color gradients in real-time based on the user's logged mood,
  stress, and sleep metrics. The shader runs directly on the user's GPU.
- Stability: Includes custom shader modulo division patches to prevent flickering
  and visual glitches across diverse device profiles.

C. BURNOUT RISK CLASSIFIER (ML PIPELINE)
- Predictor Model: A scikit-learn Decision Tree Classifier runs inside the app
  memory. It evaluates a 12-feature matrix (daily metrics, average mood, stress, 
  sleep trends over 7 days, consecutive bad days, and sentiment score) to output
  a burnout risk prediction (Low, Medium, High).
- Explainable AI (XAI): The dashboard displays key metrics driving the burnout
  prediction so users can identify specific factors impacting their well-being.
- Fairness & Audit:
  * Bias Audits (scripts/bias_audit.py): Audits model predictions across sleep 
    and stress quintiles, flagging accuracy drops greater than 5%. Results are 
    rendered on the admin dashboard.
  * Drift Monitoring (scripts/monitor_drift.py): Checks the active prediction
    distribution against a baseline to detect model performance degradation.
  * Model Card (app/ml/model_card.md): Documents model specifications, training 
    details, limitations, and ethical considerations.
  * Database Log Extraction (scripts/export_db_to_training.py): Extracts real user
    database entries, calculates rolling 7-day values, and compiles/merges them
    into the ML training CSV, facilitating the transition to real-user data.

D. GDPR COMPLIANCE & EXPORTS
- Right to be Forgotten: Users can delete their account from the settings page, permanently purging their profiles, credentials, logs, and goals.
- Data Portability: Users can export their entire history in CSV format or as a formatted PDF report generated using ReportLab (app/utils/pdf_report.py).
- Database Soft Deletes: Integrated `deleted_at` fields on Users and MoodLogs, preserving administrative analytical histories while performing cascading purges upon hard user account deletion.

E. SECURITY & HARDENING
- Encrypted Journaling: Reflection logs are encrypted at rest using AES-256 Fernet symmetric cryptography. The decryption key is loaded from the environment variables, protecting raw text entries in the database.
- Dynamic Admin Invite Tokens: Implemented database-backed invitation tokens generated and managed from the Admin console, removing static config-file registration codes.
- Crisis Safety Protocol: If the model predicts a High burnout risk, the application renders emergency resource links (e.g., 988 Suicide & Crisis Lifeline in the US, Kiran national helpline in India).
- Rate Limiting: Key actions (login, registration, API endpoints) are rate-limited using flask-limiter and a Redis backend.

F. PWA, CACHING & WEB STANDARDS
- Offline Mode: PWA capabilities are supported via manifest.json and a custom Service Worker (sw.js). When offline, users are served cached static resources and a custom offline.html fallback.
- Multi-Tab State Sync: Integrated a browser BroadcastChannel sync system that broadcasts refresh triggers across all open tabs on check-in or preference edits, alerting users via a glassmorphic toast notification.
- Precise Query Caching: Enabled caching on the goals list page and daily heatmap JSON API, with selective invalidation keys cleared immediately upon log edits/creations.
- Accessibility: Structured layout landmarks, skip-to-content links, clear focus indicators, `aria-live` announcement regions, and explicit orb canvas descriptions.
- Performance: Decohesion of heavy packages (THREE.js and Chart.js load only on necessary pages), async Google Fonts integration, and custom CSS minification.
- Sticky Footer Layout: Implemented a Flexbox-based sticky footer layout on the body (display: flex; flex-direction: column) and main content area (flex: 1 0 auto). Bounded the footer container width to 1240px and centered it using auto-margins.

G. ETHICAL ML & USER AUTONOMY
- ML Predictions Preference Toggle: Integrated a profile toggle setting to opt-out of machine learning analysis. When disabled, the ML classifier pipeline is bypassed and logs fallback to a static "Low" risk.
- Warnings Reveal Shield: Covered high-risk burnout warnings and crisis helplines on the user dashboard behind an opt-in reveal shield to prevent immediate, system-generated user anxiety.
- Model Pipeline Joblib Migration: Replaced insecure pickle serialization with joblib format loading and retraining configurations across the training, prediction, bias audit, and drift monitor scripts.

5. QUICK START & OPERATIONS MANUAL
--------------------------------------------------------------------------------

A. LOCAL DEVELOPMENT SETUP
```bash
# 1. Prepare environment
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt -r requirements-dev.txt

# 2. Configure variables
cp .env.example .env
# Open .env and add your SECRET_KEY and ENCRYPTION_KEY

# 3. Apply database schemas
flask db upgrade

# 4. Generate local training data and train the model
python -m app.ml.generate_data
python -m app.ml.train

# 5. Extract database logs (optional, when real logs exist in DB to retrain on)
python scripts/export_db_to_training.py --mode merge
python -m app.ml.train

# 6. Run the application
python run.py
# Open: http://localhost:5000
```

B. RUNNING TESTS & CODE AUDITS
```bash
# Run the test suite
pytest -v

# Check PEP-8 Compliance
flake8 app/

# Run the local bias audit
python scripts/bias_audit.py

# Check for model drift
python scripts/monitor_drift.py
```

C. CONTAINERS (DOCKER)
```bash
# Start Flask application and a Redis container locally
docker-compose up -d --build
```

6. PRODUCTION DEPLOYMENT (RENDER BLUEPRINT)
--------------------------------------------------------------------------------
DayTone utilizes infrastructure-as-code configurations in render.yaml to provision
a live production stack containing:
1. Python Web Service: Configured to pull from GitHub, compile dependencies, run
   database migrations automatically inside the startCommand runtime, and serve 
   traffic via gunicorn.
2. Managed PostgreSQL Instance: Houses persistent data. Boolean default values 
   and columns are fully PostgreSQL-compliant.
3. Private Redis Instance: Utilized as a session store and token bucket registry
   for rate-limiting requests securely. Protected from outside networks using private
   subnet settings (ipAllowList: []).

Live deployed instance: https://daytone-piyi.onrender.com
