================================================================================
              DAYTONE MOOD ANALYSER - PROJECT WORKFLOW & HISTORY
================================================================================
This document provides a comprehensive chronological record of the development,
architecture, security, ML pipeline, and cloud deployment of the DayTone
wellness-tracking application, from its initial codebase scratch state to the
fully optimized production deployment.

--------------------------------------------------------------------------------
PART 1: PROJECT OVERVIEW & TECH STACK
--------------------------------------------------------------------------------
DayTone is a production-grade, GDPR-compliant Flask web application designed for
daily mental wellness tracking and burnout prediction. 

Core Technologies:
- Backend: Python Flask, Flask-SQLAlchemy, Alembic (Migrations), Flask-Login
- Database: SQLite (Local) / PostgreSQL (Production)
- Cache & Rate Limiter: Redis, Flask-Limiter
- Machine Learning & NLP: Scikit-learn (Decision Tree Classifier), local 
  VADER/sentiment analysis, Cryptography (AES-256 Fernet)
- Frontend: Vanilla HTML5/CSS3 (Harmonious Dark Theme), Vanilla JavaScript,
  THREE.js (Simplex Noise Shader 3D Orb), Chart.js (Interactive Dashboards)
- DevOps & CI/CD: Docker (Multi-stage), Docker Compose, GitHub Actions
- Cloud Infrastructure: Render Blueprint (Infrastructure-as-Code)

--------------------------------------------------------------------------------
PART 2: CHRONOLOGICAL DEVELOPMENT WORKFLOW
--------------------------------------------------------------------------------

PHASE 1: INITIAL CODEBASE SETUP & FOUNDATIONS (THE SCRATCH START)
- Project Initialization: Initialized the Flask application structure, configured
  environment variables using python-dotenv, and set up git version control.
- Core Database Schema: Designed the initial SQLite relational models (User, 
  MoodLog) using Flask-SQLAlchemy and Flask-Login for secure session management.
- Daily Log Collection: Implemented form collection for daily user check-ins, 
  capturing mood scores (1-10), sleep hours, stress levels (1-10), physical 
  activity done (boolean), and social interaction (boolean), along with raw 
  journal reflection notes.

PHASE 2: 3D SHADER ORB & VISUAL INTERACTION
- THREE.js Integration: Replaced static elements with a dynamic 3D WebGL mood 
  orb rendered using THREE.js.
- Simplex Noise Shader: Implemented custom vertex and fragment shaders utilizing 
  simplex noise to morph the orb's shape and color gradients dynamically in 
  real-time based on the user's daily mood metrics.
- Mathematical Fixes: Corrected coordinate mapping and modulo division bugs in 
  the noise shader coordinates to ensure flawless, flicker-free rendering across 
  all modern GPU drivers.

PHASE 3: MACHINE LEARNING & ANALYTICS PIPELINE
* Decision Tree Classifier: Trained a scikit-learn multiclass classifier to 
  predict burnout risk (Low, Medium, High) across 12 distinct user metrics.
* Explainable AI (XAI): Designed driver cards on the dashboard showing feature
  importance lists dynamically explaining the primary causes behind an individual's
  burnout score (e.g. sleep duration, stress levels).
* Bias & Fairness Audit: Developed a standalone testing utility
  (`scripts/bias_audit.py`) executing audits on demographic groups (stress/sleep
  quintiles), flagging accuracy drops above 5%. Integrated a visual bias audit report
  directly inside the Admin dashboard.
* Model Card Documentation: Authored an ML Model Card (`app/ml/model_card.md`) 
  following standard documentation conventions detailing training configurations,
  evaluation, limitations, and ethical considerations.
* Data Drift Monitoring: Created `scripts/monitor_drift.py` checking prediction
  drift and model degradation against a saved baseline.
* Database Log Exporter: Created a database extraction utility (`scripts/export_db_to_training.py`)
  that compiles real user logs into a 12-feature training matrix, supporting both 
  data augmentation (merging real and synthetic data) and complete replacement.

PHASE 4: USER & ADMIN CONSOLE IMPROVEMENTS
- Admin Management Portal: Built a complete administrative dashboard allowing 
  admins to search users, edit profiles, view activity logs, and edit/delete 
  logs to maintain database integrity.
- Administrative Audit Logs: Added an AuditLog model and logging utility to 
  record admin actions (deletions, modifications, system queries) for SOC-2 
  accountability.

PHASE 5: GDPR COMPLIANCE & CONVERSION OPTIMIZATIONS
- GDPR Data Management:
  * Right to be Forgotten: Integrated account deletion options that cascade and
    permanently erase all personal logs and profiles.
  * Data Portability: Added options for users to export their complete mood 
    history in CSV and PDF formats (using ReportLab in app/utils/pdf_report.py).
- Optimization & A/B Testing:
  * Wrote app/utils/ab_testing.py to manage conversion funnels and test alternative 
    layouts.
  * Implemented user goals tracking to encourage daily check-in habits.

PHASE 6: SECURITY HARDENING & PROGRESSIVE WEB APP (PWA)
- Encrypted Journal Notes: Integrated AES-256 Fernet symmetric cryptography using 
  the python 'cryptography' library. User journal notes are encrypted at rest 
  before database insertion and decrypted on the fly in memory.
- Crisis Safety Trigger: Programmed emergency safety card alerts (988 suicide 
  lifeline, Samaritans, global support linkages) that display on dashboards 
  instantly when a High burnout risk is predicted.
- PWA Features: Configured static asset manifest (manifest.json), offline 
  rendering fallback (offline.html), and a caching Service Worker (sw.js) for 
  offline load support and home screen installation.

PHASE 7: PERFORMANCE & ACCESSIBILITY POLISH
- Web Page Optimization:
  * Deferred non-critical libraries (three.min.js, chart.umd.min.js) to load 
    asynchronously only on pages where they are used.
  * Implemented asynchronous font loading with media query print stylesheets to 
    eliminate render-blocking elements.
  * Developed scripts/minify_css.py to compress custom stylesheets.
  * Placed early inline script theme checks in the head to prevent dark-mode flash.
- Accessibility Standards: Refined focus-ring keyboard navigation, added navbar 
  toggle ARIA labels, and structured landmark tags to achieve a 100/100 WCAG score.
- Sticky Footer Layout: Implemented a Flexbox-based sticky footer layout. Bounded 
  the footer container width to 1240px and styled it with auto-margins to align 
  with the main layout grid, resolving the floating-footer bug on short content pages.
- CI/CD Pipelines: Created .github/workflows/ci.yml with pytest, flake8 PEP-8 
  validation, and automated security scanning.

PHASE 8: RENDER CLOUD DEPLOYMENT
- Render YAML Configuration: Authored render.yaml declaring a Flask app service, 
  a managed PostgreSQL database, and a Redis instance.
- Free Tier Workarounds:
  * Configured internal Redis networking via empty IP allowlists (ipAllowList: []).
  * Resolved Alembic migration limitations by executing "flask db upgrade" 
    during startCommand instead of buildCommand.
  * Modified default constraints (PostgreSQL boolean defaults set to false).
- Preferred Activity Validation Fix: Resolved a bug where selecting activities other 
  than Walk (such as Run, Cycle, Gym, Swim) returned a validation error. Migrated the 
  UserProfile database column type to String(50), synchronized WTForms validators, 
  and updated the register and settings templates to handle all 8 activities.
